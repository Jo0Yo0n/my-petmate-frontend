# 프론트 미결정 사항

아직 확인하거나 결정해야 할 사항만 관리한다. 확정된 범위·기술·정책은 각 담당 문서가 기준이며, 이 목록의 제안·보류 내용을 승인된 요구나 현재 변경의 근거로 사용하지 않는다.

## 남은 사항

| 항목                        | 확인·결정할 내용                                                                                                                                                            | 확인·결정할 시점                                                                    |
|-----------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------|
| 첫 실행 환경                | iPhone 모델·iOS·같은 LAN 사용·Xcode/서명 준비, SDK·Node 정확한 버전과 호환성                                                                                                | 첫 실행 준비. 환경 점검으로 확인 가능한 부분은 먼저 조사한다.                       |
| 디자인 자료와 배포 에셋     | 새 에셋의 최종 기기 크롭·앱 아이콘·스플래시 등 배포 준비 확인                                                                                                               | 해당 UI 구현 전. 목업을 배포 에셋으로 간주하지 않는다.                              |
| F2 구현 도구·정책           | 지오코딩 품질과 도구, 임시 저장의 내용·복원·삭제·계정 전환 정책, 이미지 처리 방식                                                                                           | F2 요구·계약 대조 후. 지금 의존성을 설치하지 않는다.                                |
| 백엔드 플랫폼 범위 정합화   | [백엔드 seed의 constraints](../../my-petmate-server/docs/seed.yaml)는 Android·iOS를 언급하지만 프론트 MVP는 iPhone 우선으로 합의했다. 백엔드 문서의 정합화 여부를 결정한다. | 백엔드 문서 변경을 별도로 승인받을 때. 현재 프론트 범위와 서버 계약은 유지한다.     |
| 기존 계정 상태 마이그레이션 | identityVisibility의 기존 값은 discoveryStatus와 의미가 다르다. 기존 계정의 새 찾기 상태 부여·사용자 확인 정책을 정한다.                                                    | 백엔드 DTO·DB 마이그레이션 구현 전. 문서 변경만으로 기존 값을 자동 대응하지 않는다. |

## 관리 방법

- 실제로 확인·결정이 필요한 항목만 추가하고, 내용과 확인·결정할 시점을 적는다. 환경에서 확인할 수 있는 사실은 먼저 조사한다.
- 판단이 필요한 시점에 문제·근거·대안·권장안을 설명하고 사용자와 결정한다. 그 전에 임의로 확정하거나 구현하지 않는다.
- 확인·결정이 끝나면 결과와 필요한 이유를 해당 계획·기능·개발 규칙 문서에 반영한 뒤 이 목록에서 제거한다. 완료된 결정 이력은 이 문서에 쌓지 않는다.

## 지역 카탈로그 구현 전 확인

읍면동만 최대 3개 선택으로 확정했다. 전국 데이터 원천·안정 ID·갱신 방식과 기존 주 활동 지역 문자열의 정규화·이관은 구현 전에 결정·검증한다. 목업의 서울/마포구 4개 동 및 demo ID는 실제 공식 지역 데이터가 아니다.
