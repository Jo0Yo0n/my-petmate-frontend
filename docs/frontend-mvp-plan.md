# My Petmate iPhone 프론트엔드 MVP 계획

## 현재 위치

현재 구현 대상은 **F0→F1**이며, 두 단계의 앱 구현은 아직 시작하지 않았다. 작은 구현 단위와 완료 기준은 [F0·F1 구현 계획](f0-f1-implementation-plan.md)을 따른다.

## 범위

- MVP는 iPhone·한국어·한국 지역 사용자·밝은 모드·TestFlight 베타를 대상으로 한다. Android·웹·다크 모드·App Store 공개 출시는 제외한다.
- 지금 구현할 범위는 F0→F1이다. F2 이후 기능은 아래 개괄 계획으로 남긴다. 백엔드 seed의 Android·iOS 범위와의 문서 정합화는 백엔드 문서 변경 승인 시 확인한다.
- 보호자 닉네임·선택 사진 조회/수정과 가입·내 정보의 주 활동 지역·활동 가능 요일/시간 설정을 포함한다. 보호자 자기소개·email·비밀번호 편집은 만들지 않는다. 본인 정보 설정과 탈퇴는 F1에 포함한다.
- 소셜 로그인·전화 인증·푸시·오프라인 메시지 큐·지도 탐색·자동완성·현재/실시간 위치·좌표 입력/저장·거리 계산/표시·결제·공개 평점·그룹 산책·관리자 화면은 제외한다. 종료 약속의 비공개 평가는 F6 범위다.
- 백엔드와 기능별로 교차한다: M1→F1→M2→F2. 프론트 통합·자동 검증·실제 iPhone 확인 전 다음 단계로 자동 진행하지 않는다. 백엔드 상태 변경은 해당 저장소의 절차와 별도 요청을 따른다.

서버 계약 확정 후 프론트의 연동 과제는 [프론트 기술 부채](technical-debt.md), 서버의 계약 검토는 [백엔드 M2 계획](../../my-petmate-server/docs/backend-mvp-plan.md#m2-반려견-프로필)에서 관리한다.

## 기반 선택과 기준 문서

- React Native·Expo·TypeScript strict로 시작한다. 초기 실행 환경과 생성 전 확인 절차는 F0·F1 구현 계획을 따른다.
- 일반 RN 컴포넌트·React 기본 상태를 사용한다. 화면 이동은 Expo Router, 세션 유지에는 SecureStore를 도입한다. 추가 상태·폼·UI 의존성은 필요가 확인될 때 판단한다.
- OpenAPI로 타입을 생성하고 작은 fetch 클라이언트를 사용한다. REST 형식·오류·요청 ID의 기준은 [백엔드 AGENTS](../../my-petmate-server/AGENTS.md)가 연결한
  문서다. 프론트에서 별도 계약을 만들지 않는다.
- 인증의 저장·복원·갱신·종료·내 정보·탈퇴·실패·테스트는 [인증 흐름](auth-flow.md)을 따른다.
- 화면 동작은 [화면 정의](screen-definition.md), 시각 규칙은 [UI Foundation](ui-foundation.md), 도구·개념·환경은 [프론트 가이드](frontend-guide.md)
  에
  둔다.

## 개괄 계획

단계별 상태는 이 표에서 관리한다. 구현 단위별 상태와 완료 판정에 필요한 근거는 해당 상세 계획에서 현재 상태로 관리하고, 검증·설명까지 끝난 결과를 기준으로 단계 상태를 갱신한다. 문서·PNG의 존재만으로 앱
구현·기기 검증 완료를
판정하지 않는다.

각 단계 시작 때 최신 계약·화면·이미지와 필요성을 다시 대조한다. F2 이후는 현재 구현·의존성 추가 대상이 아니다.

### 후속 단계의 미결 사항

- F2 사진: 사진 선택·편집·변환 방식은 HEIC 처리, 실패 경로와 서버 제한을 확인해 결정한다. 정사각형 편집과 최대 2048px JPEG 품질 0.8은 확정 전 구상이다.
- F1 지역 카탈로그: 전국 원천·안정 ID·갱신·기존 계정 데이터 처리의 서버 과제는 [백엔드 지역 계획](../../my-petmate-server/docs/backend-mvp-plan.md#읍면동-지역-필터--구현검증-대기)을 따른다. 주소 입력·지오코딩은 MVP에서 제공하지 않는다.
- F2 임시 저장: 내용·복원·삭제·계정 전환 정책은 해당 단계에서 결정한다.

각 단계에서 해당 항목을 상세 구현 계획으로 옮겨 결정·검증한다.
