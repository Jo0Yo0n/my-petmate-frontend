# My Petmate iPhone 프론트엔드 MVP 계획

## 현재 위치

현재 구현 대상은 **F0→F1**이며, 두 단계의 앱 구현은 아직 시작하지 않았다. 작은 구현 단위와 검증 기록은 [F0·F1 구현 계획](f0-f1-implementation-plan.md)을 따른다.

## 범위

- MVP는 iPhone·한국어·한국 지역 사용자·밝은 모드·TestFlight 베타를 대상으로 한다. Android·웹·다크 모드·App Store 공개 출시는 제외한다.
- 지금 구현할 범위는 F0→F1이다. F2 이후 기능은 아래 개괄 계획으로 남긴다.
- 보호자 닉네임·선택 사진 조회/수정은 포함한다. 보호자 자기소개·email·비밀번호 편집은 만들지 않는다. 본인 정보 설정과 탈퇴는 F1에 포함한다.
- 소셜 로그인·전화 인증·푸시·지도 탐색·자동완성·현재/실시간 위치·결제·공개 평점·그룹 산책·관리자 화면은 제외한다. 종료 약속의 비공개 평가는 F6 범위다.
- 백엔드와 기능별로 교차한다: M1→F1→M2→F2. 프론트 통합·자동 검증·실제 iPhone 확인 전 다음 단계로 자동 진행하지 않는다. 백엔드 상태 변경은 해당 저장소의 절차와 별도 요청을 따른다.

아직 확인·결정할 환경·UX·기술·문서 정합화 항목은 [미결정 사항](decisions.md)에서 관리한다.

## 기반 선택과 기준 문서

- React Native·Expo·TypeScript strict로 시작한다. 초기 실행 환경과 생성 전 확인 절차는 F0·F1 구현 계획을 따른다.
- 일반 RN 컴포넌트·React 기본 상태를 사용한다. 화면 이동은 Expo Router, 세션 유지에는 SecureStore를 도입한다. 추가 상태·폼·UI 의존성은 필요가 확인될 때 판단한다.
- OpenAPI로 타입을 생성하고 작은 fetch 클라이언트를 사용한다. REST 형식·오류·요청 ID의 기준은 [백엔드 AGENTS](../../my-petmate-server/AGENTS.md)가 연결한 문서다. 프론트에서 별도 계약을 만들지 않는다.
- 인증의 저장·복원·갱신·종료·내 정보·탈퇴·실패·테스트는 [인증 흐름](auth-flow.md), 설명·검증 절차는 [개발 규칙](development-conventions.md)을 따른다.
- 화면 동작은 [화면 정의](mvp-screen-map.md), 시각 규칙은 [UI Foundation](ui-foundation.md), 도구·개념·환경은 [프론트 가이드](frontend-guide.md)에 둔다.

## 개괄 계획

단계별 상태는 이 표에서 관리한다. 구현 단위별 상태와 검증 증거는 해당 상세 계획에서 관리하고, 검증·설명까지 끝난 결과를 기준으로 단계 상태를 갱신한다. 문서·PNG의 존재만으로 앱 구현·기기 검증 완료를 판정하지 않는다.

각 단계 시작 때 최신 계약·화면·이미지와 필요성을 다시 대조한다. F2 이후는 현재 구현·의존성 추가 대상이 아니다.

### 후속 단계의 기존 구상과 재검토 지점 (완료 시 삭제)

- F2 사진: 사진첩 입력·정사각형 편집·최대 2048px JPEG 품질 0.8 변환은 기존 구상이다. HEIC 입력·실패·서버 제한과 대조한 뒤 도구를 결정한다. 비공개 S3 저장·만료 조회 URL은 서버 계약을 따른다.
- F2 지역: 한국어 구·동/도로명 입력→지오코딩→지역명 확인을 구상했다. 현재 위치 권한·지도·자동완성은 제외한다. iOS 지오코딩의 실제 품질을 확인한 뒤 도구를 결정하고, 부족할 때만 Kakao Local API 프록시를 검토한다. 서버 근사 좌표·원본 미보존 정책을 따른다.
- F2 로컬 임시 저장은 기존 계획이며 저장 내용·복원·삭제·계정 전환 정책을 해당 단계에서 결정한다.
- F3 필터는 세션의 현재 추천 요청에만 적용한다. 찾기 상태 변경은 다음 추천·관심 요청부터 반영하고 기존 받은 관심 응답·match/chat/약속을 유지한다.
- F5는 인증 성공 후 전송, 갱신 후 재연결·REST 재조회, 저장 확인 이벤트를 프로토콜에 맞춘다. 상태 변경·차단 후 조회 데이터와 연결/입력을 정리한다. Query 도입은 아직 확정하지 않았다. 푸시·오프라인 메시지 큐는 제외한다.
- F6는 DatePicker·시트를 구현할 때 도구를 결정하며 SwiftUI 사용을 전제하지 않는다. 신고·평가 필드·한도는 계약을 따른다.
- F8은 Apple Developer 계정, 아이콘·스플래시·사진 권한 설명·개인정보 처리방침·베타 심사 정보를 준비한다. EAS production 빌드는 배포 경로의 대안이며 필수로 고정하지 않는다.
- 개발 중 두 번째 사용자는 API/WebSocket 클라이언트로 대체할 수 있지만 실제 양방향 iPhone 채팅 검증은 F8에서 수행한다.

## 승인 계약 정합화 (2026-10-22)

추천은 큰 사진 목록 → 상세 → 관심·패스 버튼을 사용한다. 받은 관심은 찾기 상태와 무관한 F4 공통 기능이며 매칭 탭에서 접근한다. 서버의 discoveryStatus 교체는 M1 체크리스트에 검증 완료 기록이 있으며, 받은 관심 API는 M4 구현 대기다. M1 전체 완료·프론트 게이트와 닉네임·사진 추가 계약은 여전히 대기다. 디자인 원본은 [수정 가능한 화면 자료](design-assets/editable-wireframes/README.md)를 따른다. 디자인 정비는 F2 이후 앱 구현 착수를 뜻하지 않는다.
