# My Petmate 디자인 규칙 — Sunshine

새롭게 적용하는 햇살 디자인을 새 화면에 적용하는 기준이다. 시각 규칙은 이 문서에서 관리한다. 화면의 기능·입력·권한·상태 전이는 [화면 정의](mvp-screen-map.md), 인증은 [인증 흐름](auth-flow.md), 요청·응답은 백엔드 계약을 따른다. 디자인을 맞추기 위해 기능이나 보안 정책을 바꾸지 않는다.

기준 화면은 [로그인·회원가입·추천 목록·상세·채팅](design-assets/editable-wireframes/sunshine-board.html)이다. 전체 37개 화면의 구성·동작 원본은 [HTML/CSS 와이어프레임](design-assets/editable-wireframes/index.html)이다. 과거 PNG·시안·중복 보드는 삭제했으며 PNG를 전체 화면 기준으로 관리하지 않는다. 기반 CSS의 기본값을 새로운 시각 기준으로 사용하지 않는다. 다른 화면까지 디자인 적용을 마쳤다는 뜻은 아니다. 실제 RN 앱·API 연결·기기 검증은 별도이며 현재 프론트 구현 단계도 변경하지 않는다.

## 1. 디자인 방향

**햇살 좋은 날, 편안하게 함께 걷는 느낌**을 만든다. 사진은 반려견을 먼저 보여주고, 정보는 차분히 읽히며, 다음 행동은 분명해야 한다.

- 햇살 골드는 주요 행동·선택에, 크림은 화면 배경에, 짙은 브라운은 글자에 사용한다.
- 여백·글자 크기·정렬·사진으로 계층을 만든다. 장식과 중첩된 카드로 정보를 구분하지 않는다.
- 추천은 사진 중심, 입력은 명확한 label 중심, 채팅은 대화 중심으로 구성한다. 모든 화면을 사진이 큰 인증 화면처럼 만들지 않는다.
- 한 화면에서 가장 중요한 행동은 하나의 골드 버튼으로 강조한다. 취소·패스·위험 행동은 구분한다.
- 새 래스터 이미지를 생성하지 않고 기존 독립 에셋을 활용한다. 이미지에 글자·입력·버튼을 합성해 화면을 만들지 않는다.
- 정확한 위치·인기 지표·공개 별점·점수 퍼센트·게임형 스와이프 표현은 사용하지 않는다. 비공개 약속 평가는 해당 화면 정의를 따른다.

햇살 미리보기는 `tokens.css → styles.css → design.css → sunshine.css` 순서로 스타일을 읽는다. 마지막 sunshine.css가 이전 값을 덮어쓴다. CSS 변수는 색상을 역할별 이름으로 재사용하는 장치이며 RN 컴포넌트와 자동 공유되는 코드는 아니다.

새 화면은 가까운 패턴을 먼저 재사용한다. 새로운 라이브러리·테마·범용 컴포넌트 계층은 이번 규칙의 전제가 아니다. 현재 일부 선택자는 `[data-view="signup"]`처럼 화면에 한정되어 있으므로 다른 화면에 복사할 때 실제 적용 범위를 확인한다. 기존 화면을 깨뜨리는 전역 덮어쓰기는 피한다.

## 3. 색상

밝은 모드가 기준이다. 골드 버튼에는 흰색 대신 **잉크색 글자·아이콘**을 사용한다. 골드를 흰 배경의 작은 본문 글자색으로 사용하지 않는다.

| 역할            | 현재 변수 또는 값                | 사용                                 |
|-----------------|----------------------------------|--------------------------------------|
| 주요 행동       | `--sun-gold` · `#F2CD70`         | 주요 버튼·내 메시지·브랜드 포인트    |
| 눌림/hover      | `--sun-gold-pressed` · `#E4BA52` | 주요 행동의 피드백                   |
| 화면 배경       | `--sun-cream` · `#FAF8F2`        | 기본 화면·상세 정보 영역             |
| 표면            | `--sun-paper` · `#FFFEFB`        | 시트·수신 메시지·행동 영역·선택 타일 |
| 주요 글자       | `--sun-ink` · `#332E24`          | 제목·본문·골드 위 글자               |
| 보조 글자       | `--sun-secondary` · `#6C6457`    | 설명·보조 정보                       |
| 선택 배경       | `--sun-tint` · `#F7EDD0`         | 선택 타일·궁합 영역·작은 상태 표시   |
| 보조 강조/성공  | `--sun-olive` · `#566341`        | 일치 안내·작은 보조 아이콘           |
| 구분선          | `--sun-line` · `#E4DED0`         | 비상호작용 구분선·표면 경계          |
| 입력·선택 경계  | `#978B75`                        | 식별이 필요한 입력·성별 타일 경계    |
| focus/선택 강조 | `#8D6B24`                        | 포커스·선택 테두리·보조 아이콘       |
| 오류·위험       | `--color-danger` · `#B42318`     | 필드 오류·탈퇴·차단·신고·매칭 종료   |

컴포넌트별 표면 예외는 현재 원본을 따른다. 텍스트 필드는 `#FFFEFA`, 채팅 대화 배경은 `#F3F0E7`, 주요 버튼의 비활성 배경은 `#E8E3D8`다. 같은 역할의 새 색을 화면마다 추가하지 않는다.

일반 텍스트 대비는 4.5:1, 큰 글씨·식별에 필요한 컨트롤 경계는 3:1 이상을 확인한다. 기존 대비 계산에서 잉크/골드는 8.83:1, 보조 글자/크림은 5.50:1, 입력 경계/표면은 3.32:1이다. 다른 배경·투명도·이미지 위에 옮기면 다시 계산한다. 이 수치만으로 접근성 준수를 선언하지 않는다.

## 4. 타이포그래피와 문구

`-apple-system`, `BlinkMacSystemFont`, `Apple SD Gothic Neo`, `sans-serif` 순의 시스템 계열을 사용한다. 별도 웹 폰트는 필요하지 않다. RN 구현에서는 iOS 시스템 글꼴과 Dynamic Type을 확인한다.

| 역할             |             기본 크기 | 굵기·사용 예                                  |
|------------------|----------------------:|-----------------------------------------------|
| 환영/가입 제목   |                  30px | 700~750 · `.login-copy h2`, `.signup-copy h2` |
| 추천 목록 제목   |                  34px | 750 · `.recommendation-intro h2`              |
| 반려견 이름      | 목록 30px / 상세 36px | 750 · `.identity-line`                        |
| 섹션 제목        |               20~21px | 600~700 · 소개·산책 조건                      |
| 폼 섹션 제목     |                  17px | 600 · `.sun-section-heading h3`               |
| 주요 읽기 본문   |               15~16px | 400 · 소개·채팅·약속 내용                     |
| 입력 값          |                  16px | 400 · `.sun-field input`                      |
| 필드 label       |                  14px | 600 · `.sun-field-label`                      |
| 보조 설명·피드백 |               12~13px | 400 · 안내·메타데이터·오류                    |
| 행동 버튼        |          보통 15~17px | 600~700 · 크기보다 대비·위치로 강조           |

본문 줄 높이는 약 1.6~1.85, 제목은 약 1.2~1.3을 사용한다. 큰 제목의 자간은 약 -1px 수준이며 본문 전체에 강한 음수 자간을 적용하지 않는다. 이름·소개·오류가 길어지면 줄바꿈과 높이 확장을 허용한다.

현재 원본의 워드마크 부제·장식용 영문·탭 등에는 10~11px 예외가 있다. 새 화면의 필수 설명·오류·행동을 이 작은 크기로 만들지 않는다. 영문 eyebrow와 번호 장식은 필요할 때만 사용하며 모든 화면에 붙이지 않는다.

문구는 짧고 구체적으로 쓴다. 입력 label은 명사, 행동은 `저장`, `관심 있어요`, `약속 제안`처럼 결과를 예상할 수 있는 말로 쓴다. 오류는 문제와 수정 방법을 안내하고 서버 내부 메시지나 민감한 값을 노출하지 않는다.

## 5. 간격·형태·고정 영역

| 항목                | 기준                                                 |
|---------------------|------------------------------------------------------|
| 일반 화면 좌우 여백 | 24px. 로그인 26px, 채팅 본문 20px는 기존 화면별 예외 |
| 밀접한 요소         | 8~12px. 선택 타일 사이 8~10px                        |
| 그룹 내부           | 16~20px                                              |
| 그룹/섹션 사이      | 24~32px                                              |
| 최소 터치 영역      | 44×44px. 아이콘 그림 자체의 크기와 구분              |
| 필드                | 높이 최소 54px, 모서리 14px                          |
| 주요 버튼           | 높이 최소 50px, 모서리 17px                          |
| 사진 목록           | 모서리 26px                                          |
| 선택 타일           | 유형 18px, 성별 13px, 상태 행 17px                   |
| 팝업                | 일반 확인 24px, 시트 상단 28px                       |

수치는 현재 HTML의 CSS px 기준이다. 실제 iOS point나 기기 터치 영역 검증이 끝난 값으로 간주하지 않는다. 미리보기의 390×844는 기준 프레임이고 320px은 좁은 화면 점검 폭이다. 제품 화면 크기를 두 종류로 제한하는 규칙은 아니다.

본문만 스크롤하고 헤더·탭·필요한 하단 행동은 별도 영역으로 둔다. 하단 영역 높이를 본문에서 빼서 마지막 내용이 가려지지 않게 한다. 실제 앱에서는 Safe Area와 키보드를 함께 처리한다. 고정 영역을 단순히 본문 위에 덮지 않는다.

경계와 표면으로 구분할 수 있으면 그림자는 생략한다. 모든 행을 카드로 만들거나 카드 안에 또 카드를 넣지 않는다. 미리보기의 기기 외곽 프레임·그림자·설계 도구는 실제 앱 화면 요소가 아니다.

## 6. 입력 필드와 선택

### 텍스트 필드

현재 `.sun-field`, `.sun-field-label`, `.sun-field-feedback` 구조를 재사용한다. label → 입력 → 필드 바로 아래 피드백 순서다. placeholder는 입력 예시이며 label을 대체하지 않는다.

| 상태      | 표현                                                                     |
|-----------|--------------------------------------------------------------------------|
| 기본      | 밝은 표면, 1px 입력 경계, 내부 14px 16px 여백                            |
| 포커스    | 진한 골드 경계, 바깥 3px 옅은 골드 ring, 2px 간격                        |
| 오류      | 2px danger 경계, 구체적인 문구, `aria-invalid="true"`                    |
| 성공 확인 | 올리브색 문구. 실제 확인한 내용만 표시                                   |
| 비활성    | 낮춘 채도의 표면·경계와 진행 안내. 색 변화만으로 처리 중을 설명하지 않음 |

오류 경계를 2px로 바꿀 때 내부 여백을 1px 줄여 요소가 움직이지 않게 한다. 키보드 포커스 표시를 제거하지 않는다. `aria-labelledby`는 고정된 label, `aria-describedby`는 별도 피드백을 가리킨다. 안내 문구가 추가되면서 입력의 접근 가능한 이름이 바뀌지 않게 한다.

다음은 같은 패턴을 새 화면에 적용하는 구조 예시다. ID는 화면 안에서 중복되지 않아야 한다. 유효성·저장 동작은 해당 화면 규칙에 연결한다.

```html
<label class="sun-field">
  <span class="sun-field-label" id="place-label">장소</span>
  <input id="place" name="place" type="text"
    aria-labelledby="place-label" aria-describedby="place-feedback"
    placeholder="만날 장소를 입력해 주세요" required>
  <span class="sun-field-feedback" id="place-feedback" aria-live="polite"></span>
</label>
```

비밀번호 확인은 가입 화면의 필수 로컬 비교다. 비밀번호 원문을 정규화하지 않고 비교하며 미입력·불일치하면 진행하지 않는다. 원 비밀번호가 바뀌면 결과도 갱신한다. 확인 값은 API 전송·영속 저장·로그에 포함하지 않는다. 서버 비밀번호 검증을 대신하는 보안 장치는 아니다.

### 선택 타일

보호자 유형은 3열 타일, 찾기 상태는 설명이 있는 세로 선택 행을 참고한다. 단일 선택은 radio, 다중 선택은 checkbox 의미를 유지한다. 타일 전체가 선택 영역이고 기본 선택 표시는 글자·아이콘·테두리와 함께 읽혀야 한다.

선택 시 tint 배경과 2px 진한 경계, radio의 점 표시를 함께 사용한다. 색상만 바꾸거나 선택 전후 크기를 바꾸지 않는다. 큰 글씨에서 설명이 길어지면 타일의 높이를 늘린다.

**성별 선택은 여성·남성 2열 타일만 둔다.** 이를 둘러싸는 별도 배경 박스·외곽 테두리·내부 패딩은 두지 않는다. 위에 `성별` label, 아래에 최초 설정 안내를 둔다. 개인 선택 시에만 나타나며, 최초 성별 보존·설정 화면의 읽기 전용 정책은 인증 흐름을 따른다. 다른 정보 묶음에도 의미 없는 바깥 박스를 추가하지 않는다.

## 7. 화면 패턴

### 인증·입력 화면

로그인은 워드마크·기존 사진·짧은 환영 문구·입력·주요 행동·가입 이동 순서다. 아치형 사진은 환영 화면의 특징이며 등록·설정 폼마다 반복하지 않는다. 현재 사진 높이는 200px다.

가입은 소개 → 기본 입력 → 보호자 유형과 조건부 성별 → 찾기 상태 → 제출 순서다. 긴 폼은 자연스럽게 스크롤한다. 유형·성별·찾기 상태는 승인된 화면 정의대로 미선택에서 시작한다. 인증 화면에는 일반 보호 탭과 공통 앱 헤더를 먼저 노출하지 않는다.

### 목록

후보 탐색은 `.sun-candidate`를 참고한다. 기준 반려견·필터 도구 아래에 큰 사진 → 이름·나이/크기 → 활동 지역·근사 거리 → 짧은 궁합 이유 → 보호자 정보 순서로 읽힌다. 현재 사진 높이는 300px이며 사진 위에는 작은 궁합 라벨 정도만 둔다. 전체 항목을 눌러 상세로 이동하며 스와이프로 판단하게 하지 않는다.

매칭·반려견 관리처럼 빠르게 찾는 목록은 사진·제목·필요한 보조 정보·상태를 가진 행과 구분선을 사용한다. 추천의 큰 사진 형식을 모든 관리 목록에 적용하지 않는다. 받은 관심에 추천 궁합을 임의로 붙이거나 근거 없는 배지를 만들지 않는다.

### 상세

`.sun-detail-hero`, `.sun-profile`, `.compatibility`, `.profile-section`, `.profile-facts`를 참고한다. 사진 → 이름/기본 정보 → 보호자 → 궁합과 이유 → 소개 → 산책 시간/조건 순서다. 현재 390px 시안의 사진 높이는 354px이며 크림 정보 표면이 사진 아래에서 17px 겹쳐 둥근 상단으로 이어진다.

사진 비율을 고정 목표로 삼아 이름을 첫 화면 밖으로 밀어내지 않는다. 얼굴과 몸짓을 살리는 크롭을 먼저 확인한다. 소개·조건 전체를 읽을 수 있게 하고 주요 행동은 `.sun-detail-actions`처럼 별도 하단 도크에 둔다. 패스와 관심은 구분하며 골드로 채우는 것은 관심 버튼 하나다.

### 채팅

`.sun-conversation`, `.bubble`, `.appointment-card`, `.sun-composer`를 참고한다. 수신 메시지는 paper/ink, 발신 메시지는 gold/ink 조합이다. 말풍선은 본문에 맞춰 늘어나고 좌우 위치와 모서리로도 발신/수신을 구분한다. 약속은 대화와 구분되는 카드 하나로 표현하며 제안·성사·취소 등 서버의 실제 상태에 맞는 문구를 쓴다.

메시지 내역은 스크롤하고 입력 영역은 하단에 고정한다. 약속 제안·입력·보내기를 같은 가로줄에 둔다. **입력창·버튼의 세로 중심, 버튼 안 아이콘의 가로·세로 중심을 모두 맞춘다.** 보내기 버튼은 44×44px, 아이콘 21px다. 버튼에 `display:flex`, `align-items:center`, `justify-content:center`, `padding:0`, `line-height:1`, `flex:none`를 적용해 글자 baseline에 의해 아이콘이 내려가지 않게 한다.

연결 실패는 기존 내역을 지우는 전체 오류 대신 근처 안내로 표시한다. 개별 전송 실패는 해당 메시지 가까이에 표시한다. 화면의 재시도 버튼만으로 서버 저장 성공이나 멱등성이 보장되는 것은 아니므로 실제 전송·재연결 규칙은 프로토콜과 앱 구현 단계에서 검증한다.

### 팝업·시트·하단 탭

필터는 목록 위의 작은 모달, 약속 제안·취소·평가는 채팅 위의 시트, 단순 확인은 짧은 확인 창을 사용한다. 내부에 긴 내용이 있으면 스크롤하며 닫기·취소 경로를 제공한다. 모달의 위치는 열린 뒤의 실제 프레임 크기를 기준으로 확인하고 작은 화면 밖으로 넘기지 않는다.

하단 탭은 추천·매칭·내 반려견·내 정보 순서다. 같은 계열의 아이콘과 label을 함께 사용한다. 활성 탭은 진한 골드 계열과 작은 tint 배경으로 표시한다. 위험 행동을 골드 주요 행동으로 섞지 않는다.

## 8. 공통 상태

| 상태          | 필요한 표현                                                              |
|---------------|--------------------------------------------------------------------------|
| 처음 불러오기 | 진행 표시와 짧은 안내. 세션 복원 중에는 보호 화면을 노출하지 않음        |
| 빈 결과       | 해당 목록에 맞는 설명과 다음 행동. 미구현 기능을 빈 결과로 가장하지 않음 |
| 조회 실패     | 이해할 수 있는 문구와 재시도 경로                                        |
| 필드 오류     | 해당 필드 가까운 문구와 수정 가능한 포커스 경로                          |
| 제출 중       | 해당 행동 중복 입력 방지와 진행 문구                                     |
| 완료          | 실제 결과를 설명하고 다음 화면으로 이어지는 행동                         |
| 부분 실패     | 영향을 받은 영역에 안내. 유지 가능한 입력·기존 데이터는 유지             |

새 화면에는 정상 상태만 그리지 않는다. 실제 호출 경로에서 필요한 상태를 골라 함께 설계한다. 존재하지 않는 자동 저장·재시도·완료·서버 멱등성을 장식 문구로 약속하지 않는다. 오류 표시에는 토큰·비밀번호·내부 SQL·예외를 포함하지 않는다. 요청 ID는 필요할 때 문의 식별용으로만 노출하며 내부 구현 세부사항을 일반 흐름에 늘어놓지 않는다.

## 9. 사진·아이콘·모션

- 사진은 기존 독립 에셋을 사용한다. 얼굴과 하네스·몸짓을 가리지 않는 `object-fit:cover` 크롭을 화면별로 확인하고 사진 위 문구는 최소화한다.
- 현재 모의 반려견들은 같은 사진을 공유한다. 이는 샘플 데이터의 제한이며 실서비스의 사진 정책이 아니다. 보호자 선택 사진이 없으면 기존 미설정 자리나 user 아이콘을 사용한다.
- 아이콘은 [Phosphor regular](design-assets/editable-wireframes/assets/icons/README.md) 계열을 사용하고 [MIT 라이선스](design-assets/editable-wireframes/assets/icons/LICENSE)를 보존한다. 기본 20~22px, 터치 영역은 별도로 44px 이상 확보한다.
- 아이콘이 유일한 행동 표시라면 접근 가능한 이름을 제공한다. 장식 아이콘은 `aria-hidden`으로 중복 읽기를 막는다. SVG 라이브러리 대신 이모지·문자 기호로 새 아이콘을 그리지 않는다.
- 시트·화면 이동은 차분한 기본 전환을 사용한다. Reduce Motion을 존중하고 과한 confetti·반복 진동·카드 날리기 효과는 추가하지 않는다.

## 10. 새 화면에 적용하는 순서

1. 화면 정의에서 목적·필수 정보·행동·권한·실제 API 범위를 확인한다. 필요한 기능을 디자인 단계에서 늘리지 않는다.
2. 인증/폼·사진 목록·행 목록·상세·채팅·시트 중 가까운 기준 패턴을 고른다.
3. 공통 색상과 기존 마크업을 재사용하고, 선택자의 화면 범위와 ID 중복을 확인한다. 새 수치는 필요한 차이가 있을 때만 추가한다.
4. 대표 데이터로 정상 화면을 구성한 뒤 해당 기능의 로딩·빈 결과·오류·제출 상태를 함께 확인한다.
5. 브라우저에서 열어 아래 점검을 하고 눈에 보이는 어긋남을 수정한다. HTML은 수정 원본, PNG는 그 원본에서 만든 참고 캡처로 관리한다.

### 새 화면 확인표

- [ ] 기능·정책이 현재 화면 정의와 일치한다. 미구현 API를 동작 완료로 표시하지 않았다.
- [ ] 골드/잉크·크림/보조 글자 등 역할을 지켰고 새 색·장식·중첩 카드를 불필요하게 추가하지 않았다.
- [ ] 390px과 320px, 큰 글씨에서 가로 넘침·잘림·고정 영역의 가림이 없다.
- [ ] 긴 이름·최대 길이 소개·긴 오류를 실제 내용으로 확인했다.
- [ ] label·필수값·선택·비활성·포커스·오류가 문구와 의미로 구분된다.
- [ ] 입력창과 버튼, 버튼과 아이콘이 중앙에 정렬되고 아이콘 행동의 이름과 터치 영역이 확보됐다.
- [ ] 사진 크롭·선택 타일·스크롤·모달의 위치를 확인했다. 성별 선택에 바깥 박스가 다시 생기지 않았다.
- [ ] 주요 이동·입력·취소·재시도 경로와 필요한 실패 상태를 확인했다.
- [ ] 사용 에셋·실행 원본·캡처·실제 검증·미실행 항목을 기록했다.

브라우저 시안 확인과 실제 iPhone의 Safe Area·키보드·Dynamic Type·VoiceOver·API 통합 검증을 구분한다. 이번 문서화는 현재 디자인을 재사용할 기준을 확정한 것이며, 나머지 화면이나 실제 앱의 구현·검증 완료 처리가 아니다.
